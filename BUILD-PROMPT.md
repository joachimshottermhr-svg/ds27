## Non-negotiables

These are not style preferences. Each one is a bug that reached production in the People
First build and cost real time to find.

**Fidelity**
1. Every value comes from Figma, read off the node. Never approximate from a screenshot,
   never infer from a sibling component, never adjust to taste.
2. Record the node id beside every measured value, in a comment or the survey notes.
3. If a value cannot be verified, say so explicitly and leave it unset. Do not guess.
   A stated gap is useful; a plausible invention is not.

**Architecture**
4. Two tiers. `Primitives` (Neutral/0-900, Blue, Green, Red, Pink, Purple, Orange) feed
   `Semantic` (Background/Primary button, and so on). Component CSS references **semantic
   tokens only** - never a primitive, never a literal.
5. Before writing any rule, check whether a class for that thing already exists. In People
   First, `CircleIcon` was imported by nothing while five components hand-rolled their own
   copy of it, and all five had drifted from Figma. One shared class, always.
6. Never style a component from outside its own scope. If a parent needs a variant, the
   component exposes a modifier class - the parent does not reach in and override.
7. Valid HTML. An interactive element must never nest inside another; browsers silently
   reparent the inner one and eject the rest of the block.

**Correctness**
8. Source files are ASCII only. A single non-ASCII byte from a shell that defaults to the
   ANSI codepage propagates into every generated doc and export downstream.
9. Parse with a real parser, never a regular expression, for anything structural. Regex
   parsing produced two silent corruptions in the People First export - both looked
   entirely plausible and neither was detectable downstream.
10. Verify by driving the thing, never by asserting it works. Check exit codes: a build
    that printed output may still have failed.
11. Generate every export from one model file. Nothing hand-maintained in two places.

## Phase 3 - every component

Build the **whole system**. Every component on every page, and for each one every variant
and state Figma defines - not just the default. Work page by page in Figma's own order so
coverage is checkable against the file rather than against a list you invented.

For each component: snapshot from Figma, build the CSS, diff the render against the
snapshot, record the node ids, write the doc.

Wire the audit scripts up during the **first few components**, not at the end, so they run
against real content from the start:

- raw literals that should be tokens
- states sharing a token they cannot vary independently
- a rule that redeclares most of a shared component's rule (hand-rolled duplicates)
- interactive elements nested inside one another
- non-ASCII bytes in source

**One checkpoint, early.** After the first handful of components are complete and the
audits are running, stop and show me. This is not a reduction in scope - it is so a
systematic mistake in the approach gets caught once rather than replicated across the
whole system. Then continue straight through the rest without stopping.

Report progress as you go: which page, how many components done, how many remain.

### Known gaps in the Figma file - all reviewed and accepted

These six have been raised and signed off. **Do not stop for them, do not fix them, and do
not invent values to smooth them over.** Reproduce exactly what Figma says, and record each
one in `FINDINGS.md` at the repo root so the gap travels with the code instead of being
rediscovered later.

1. **Typography is not in the export.** No type collection exists, yet the style guide has
   a Typography frame (XL Heading, Larger Heading, Sub heading). Type is defined as Figma
   *text styles*, not variables, so read it from node `1:27` and record the node id beside
   each font size, weight and line height.
2. **Three semantic tokens hold a raw hex instead of a primitive reference** -
   `Lightmode/Chart/1`, `Darkmode/Chart/1`, `Darkmode/Background/Navigation`, all
   `#ffffff`. Emit them as the literal they are. Do not invent a primitive to point them at.
3. **The chart palette is a single white swatch.** `Chart/1` is the only chart token, and
   it is `#ffffff` in both modes. Build no charting component against it and generate no
   substitute palette - note in `FINDINGS.md` that charts are unbuildable until real chart
   tokens exist.
4. **The theme colour changes hue between modes** - `Foreground/Theme` and `Border/Theme`
   go Pink.600 to Blue.300; `Background/Theme` goes Pink.50 to Blue.800. This is intended.
   Implement it exactly, and do not "correct" dark mode toward pink.
5. **Orange has no 50 step** while every other ramp does. Emit the nine steps that exist.
   Do not interpolate a tenth.
6. **Variant axis names are inconsistently cased** in Figma - both `size`/`Size` and
   `state`/`State`. Normalise to lowercase in the CSS class names, and record the original
   Figma casing per component so the mapping is traceable.

The primary button is **Green.600**, not pink - V27's accent structure differs from People
First's, so carry nothing across by assumption.
